# Hydro Ability Audit — 2026-08-21

## Evidence and interpretation

The data contract is `src/main/resources/data/classes/hydro.json` and `src/main/resources/data/styles/hydro_styles.json`. Visual rows are from `src/main/resources/data/ability-visual-manifest.json`; a row without `legacy:true` is treated as authored, while `legacy:true` is an unauthored vanilla-spawner fallback. Runtime conclusions are based on `GameplayPlaybackManager`, `AbilityRuntimeEffects`, `AbilityExecutionPolicy`, and the runtime family adapters. The canon comparison is `docs/ability-contracts/hydro-contracts.md` (the supplied class/style canon and current-gap notes).

For legacy rows, the manifest path is recorded exactly, but the resolver only promotes `MOTM_*`/EntityEffect identifiers to runtime effects (`HytaleAssetResolver.asRuntimeEffectId`); raw `Server/Particles/...particlespawner` values are not authored MOTM EntityEffects. In addition, the runtime has broad hard-coded Hydro Wave/Dash fallbacks for some styles. Those fallbacks do not remove the manifest's per-ability authorship gap and frequently erase the style-specific identity.

## Base Class — Hydro

- **Element/theme:** Water; element field is `Flow, healing, ice`. The description explicitly combines healing water and frozen storms (`src/main/resources/data/classes/hydro.json:7`). This is coherent with the ten style lanes: ice/snow, waves, rain, steam, mist, heavy ice, ocean, rivers, and bilge.
- **Colors:** primary `#1E90FF`, secondary `#00CED1`, accent `#87CEEB` (`hydro.json:8-10`). These are a good broad Hydro base palette, but style canon calls for materially different lanes (e.g. snow white, boiling amber/steam, bilge olive, deep-ocean navy); a single generic water fallback does not preserve those identities.
- **Passive concept:** Tidal Flow: abilities heal for 3% of damage dealt; swim speed +40%; underwater oxygen capacity +50%; persistent Aqua Barrier shield at 10% max health; the barrier depletes before other Hydro overlays and starts an 8-second cooldown; Hydro uses cooldowns rather than waterskin costs (`hydro.json:35-69`).
- **Passive code behavior:** `ClassPassiveManager.tickHydroPassive` applies oxygen max modifier every tick, detects swimming/underwater state, maximizes oxygen when the current height permits breathing, adds/removes a horizontal +40% velocity boost while swimming, and maintains the barrier (`ClassPassiveManager.java:524-563`, `1033-1047`, `1120-1192`). The barrier is persistent because configured duration `0.0` is converted to `PERSISTENT_AQUA_BARRIER_TICKS`; it applies a 10%-max-health shield, adds `MOTM_Hydro_Aqua_Barrier`, and starts cooldown only after depletion (`ClassPassiveManager.java:715-763`, `1375-1401`). Ability damage calls `onDamageDealt`, which heals `damage * 0.03` only for ability-based Hydro damage (`ClassPassiveManager.java:407-422`).
- **Passive does it match?** **PARTIAL/MATCH for the stated passive.** Swim and oxygen behavior are implemented as described, and barrier precedence/lifecycle is explicit. The barrier EntityEffect uses `E_Sphere` + `Water_Bubble_Stream`, no sound/model, with no tints (`MOTM_Hydro_Aqua_Barrier.json:1-19`), so it reads as a generic sphere rather than the canon's whole-body blue bubble; `docs/ability-contracts/hydro-contracts.md:7,16` calls for one opaque blue bubble and the visual-fitness notes identify `E_Sphere` as an interim/misfit. Also, `ClassPassiveManager` contains low-water conditional-cost/damage branches (`:238-276`) whose defaults (`conditional_cost_reduction`, `conditional_damage_modifier`) are absent from the class JSON, while all ten Hydro styles have `resource_type:""`; that code path is therefore not part of the documented Hydro data behavior. The 3% spell-vamp path is correctly gated to ability damage, not weapon damage.
- **Stats/resistances/playstyle:** starts health 95, mana 120, stamina 90, armor 8, magic resist 15, attack 8, ability power 14, movement 1.0, health regen 1.5, mana regen 2.5; growth is health +5, mana +8, stamina +3, armor +0.5, magic resist +1.2, attack +0.5, ability power +1.2, health regen +0.1, mana regen +0.2 (`hydro.json:12-33`). Innate resistances are water +20%, ice +15%, fire +10%, lightning -10% (`:72-76`). Tags are healer/support/mage/control/hybrid, difficulty intermediate (`:78-81`). The stat and tag package supports a flexible support/control mage, though the lightning weakness is not surfaced in most ability visuals.
- **Overall identity verdict:** **Coherent concept, incomplete execution.** The passive is the strongest implemented part, but the per-style asset layer is mostly un-authored and generic water. The base identity is credible only when the runtime's specialized mechanics (ice projectiles, fields, summons, tethers) are used; visual identity is not yet end-to-end coherent.

## Summary

### Counts

- **Verdicts:** MATCH **1**, PARTIAL **22**, MISMATCH **7** (30 abilities).
- **Manifest authorship:** authored/non-legacy **3** (`frozen_needles`, `stalactite_crash`, `skate`); legacy/unauthored **27**. The three authored rows all use the Icicle MOTM Ice effect family; no other Hydro style has a per-ability MOTM manifest row.
- **Authored EntityEffect coverage:** Ice Cast/Travel/Impact (`Ice_Blast`, `IceBoulderTrail`, tints `#bfe9ff/#4aa3d6`) are the only per-ability authored trio. Shared Hydro Wave/Dash/Tether/Aqua Barrier effects exist in the code/resource tree, but they are family fallbacks or passive/runtime cues, not authored rows for the 27 legacy abilities.

### Top 8 issues, ranked

1. **27/30 Hydro ability rows are still `legacy:true`.** Raw vanilla spawner paths are not authored MOTM EntityEffects, so there are no per-style phase recipes, sound events, colors, or owned cleanup contracts. This is the dominant visual gap (`ability-visual-manifest.json:325-593`).
2. **Ground-strike delay/physical-object mechanics are not wired for Hydro.** `stalactite_crash`, `geyser`, and `ice_shelf` are `ground_strike`, but the terrain specs do not activate their delayed physical objects for that cast type and no delay scheduler runs; damage/effects resolve immediately. These are three MISMATCHs.
3. **Leap Frog's landing route is unreachable from data.** The special path requires `trigger:"jump_land"` (`GameplayPlaybackManager.java:1695-1698`), but `leap_frog` has no trigger. Its special landing method also records zero damage and only displaces targets (`:1988-2032`), so the stated strike/vulnerability/pool cannot occur.
4. **Rainbow is both a support-semantic and visual failure.** The field branch gives shield + speed (`FieldSupportPulseHytaleAdapter.java:114-117`) while `heal_percent` heals once at cast (`GameplayPlaybackManager.java:3144-3150`), not a 6-second healing zone; the manifest's Totem smoke is explicitly a HIGH rainbow misfit (`hydro-contracts.md:158-159`).
5. **Shared Hydro Wave/Dash fallbacks erase style identity.** `AbilityRuntimeEffects` maps Surf/Rain/Saltwater/Freshwater/Bilgewater/Boiling to the same Wave Cast/Move/Impact/Field effects (`AbilityRuntimeEffects.java:153-165`); dash abilities use Hydro Dash with `Water_Sprint`. This makes boiling, vapor, bilge, freshwater, and deep-ocean actions look like generic bright water.
6. **Field visual suppression leaves rain/snow readability gaps.** `piercing_rain` and `rainbow` proxies are disabled after a reproducible `MOTM_Hydro_Wave_Field`/Water_Bubble_Stream client crash (`FieldVisualHytaleAdapter.java:53-64`); Snowstorm also has no safe authored field proxy. Gameplay continues, but the intended persistent zones are visually unproven.
7. **Reactive/secondary mechanics are missing or replaced.** Ice Cap has no attacker-freeze hook; Tide Pool applies vulnerability rather than enemy slow and is forcibly caster-centered; Oil Spill adds a ground slow/toxic field; Abyssal Assist has no persistent pressure field. These are concept/runtime mismatches independent of legacy visuals.
8. **Object/tether family mappings are wrong for summons and naval actions.** Frosty's manifest points to Spirit_Frost instead of locked Yeti/Tamed_Frosty; Swamp Monster resolves to `Frog_Green` instead of crocodile; Anchor Haul uses `Spark_Living` plus Metal sparks instead of a chain/anchor tether. These violate physical-object-first and style-specific canon.

### Systemic patterns

- **Mechanics are ahead of visuals:** projectile, field, dash, summon, status, and tether adapters often implement a useful generic mechanic, but the manifest remains a dropped vanilla path. This explains the high PARTIAL count.
- **Generic status defaults replace authored magnitudes:** `evasion`, `attack_slow`, burn/DoT cadence, and line-control durations frequently come from runtime defaults or travel-type inference because the ability rows omit magnitudes/tick cadence.
- **Ground/terrain semantics are cast-type gated:** terrain support is strong for `barrier`/persistent zones, but similarly named `ground_strike` abilities do not receive physical/delayed terrain unless explicitly routed. Hydro's stalactite/geyser/ice-shelf concepts expose this gap.
- **Style fallback is not per-ability authorship:** shared MOTM Wave/Dash/Tether effects have useful water systems and sounds (`Water_Bubble_Stream`, `Water_Run`, `Water_Can_Splash`, `SFX_Water_MoveIn/Out`) but do not satisfy the required snow/rain/boiling/vapor/iceberg/saltwater/freshwater/bilge palettes. The only per-ability authored family is Icicle.
- **Passive identity is comparatively solid:** Tidal Flow's spell-vamp, swimming, oxygen, and persistent barrier are implemented; the Aqua Barrier visual itself remains an interim generic `E_Sphere` + bubbles composition rather than a fully authored Hydro signature.
